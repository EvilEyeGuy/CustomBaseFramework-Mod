Pieces and categories in XML

Modding

A piece is one building or one stretch of wall. It is stored as a CustomBaseFramework.PieceDef: a set of character grids plus a legend that says what each character means. The editor writes these files for you, see Pieces. You can also write them by hand. This page shows how.

Categories group pieces. They are stored as CustomBaseFramework.PieceCategoryDef and carry the rules that all their pieces share, see Categories.

All field names on this page are the exact XML names. The full list of fields is on the reference pages linked at the end.

The grids

Every grid is a list of rows. One character is one cell.

  • The first row is the north edge of the piece. The first character of a row is the west edge.
  • . and a space mean an empty cell. Nothing is done there on that layer.
  • Every other character is looked up in the legend. In the content grid it is looked up in contentZones instead.
  • All grids of a piece should have the same number of rows and the same row length. The load check reports it when they do not.
  • The size of the piece is the largest grid. There is no separate size field.
Grid What it holds
mask Which cells belong to the piece. Any character other than . counts. With clearFootprint on, only these cells are cleared before building. Without a mask, every cell that is filled on any layer counts.
terrain The floor.
things The load-bearing layer: walls, doors, furniture, everything a cell is built from. The generator reads this layer to find walls and doors.
things2 A second pass for things that share a cell with the first layer, for example a conduit under a wall or a torch on it.
things3 A third pass for the rare cell that carries three things.
plants Plants. They get a random growth and are skipped on water and on cells with a building.
roof Where a roof goes.
anchors Anchor cells, see Anchors.
anchorsOver A second anchor grid. Fill and Object anchors here place their objects on top of what already stands, without clearing the cells.
content Old loot zones, resolved through contentZones. New pieces use Fill anchors instead.

In the house above, the conduit B in things2 runs under the walls S of things. With a single layer the wall would need a gap for it.

The legend

Each <li> in legend gives one character a meaning. symbol must be exactly one character.

Field Effect
thing A ThingDef placed on this cell. Multi-cell things are placed once, from the cell you mark.
stuff The material. If it does not fit the thing, the default material is taken and a warning is logged.
rotation North, East, South or West. Default North. It turns with the piece.
terrain A TerrainDef for the floor layer.
roof A RoofDef for the roof layer. A roof cell whose entry names no roof gets RoofConstructed.
pawnKind A PawnKindDef. A pawn of the settlement's faction is spawned on this cell.
role A building role such as WALL or DOOR instead of a fixed def. CBF takes the thing from the material list of the settlement type, see Roles.
chance Chance from 0 to 1. On things, floors and roofs it is rolled per cell.
count Stack size for a stackable thing, as a range such as 5~20.
temperatur Target temperature for a cooler or heater, in degrees Celsius.
variants Alternative things or floors for this character, see below.
anchor and the fields after it Make the entry an anchor, see Anchors.

An entry must have at least one of role, thing, terrain, pawnKind, roof or anchor. Otherwise the load check reports it.

Two things change in the game, not in the file. Stone blocks as material are swapped for a stone that exists on the map tile. Floors named after a stone, such as TileGranite, are swapped the same way.

A shipped example for temperatur:

<li><symbol>K</symbol><thing>Cooler</thing><rotation>South</rotation><temperatur>-19</temperatur></li>

Variants

variants lets one character stand for several things or floors. Each cell picks one by weight, from the cell position and the settlement seed.

<li>
  <symbol>w</symbol>
  <terrain>WoodPlankFloor</terrain>
  <variants>
    <li><terrain>TileGranite</terrain><weight>0.5</weight></li>
    <li><terrain>CarpetRed</terrain><weight>0.5</weight></li>
  </variants>
</li>
  • A variant takes thing, stuff, terrain and weight. Default weight is 1.
  • If the entry itself names a thing or terrain, that counts as one more choice with weight 1. Here the planks win half of the cells.
  • A variant's stuff is only used together with its thing.
  • Variants apply to the terrain and the thing layers, not to plants.

This example is written for illustration, it is not from a shipped piece.

Piece fields

Field Effect
schemaVersion The file format. The current version is 2. Older files are upgraded on load.
categories The categories of the piece. The first is the primary one: on a conflict its rules win, then its parents, then the next category.
tag The old single category. Still read when categories is missing. Write categories.
type Building (default), WallPart or DungeonRoom. Gatehouses and wall segments are WallPart.
template true makes the piece a copy source for the editor. It is never placed.
allowRotation Default true. With false the piece is always built as drawn.
allowMirror Default true. Mirroring flips the piece east to west.
clearFootprint Default true. Removes what stands on the piece's cells before building. Water cells and pawns are left alone.
placement Overrides the category rules for this one piece, see below.
style Old field. It does not restrict where the piece is used.
traufen Places eaves from Architecture of the Rim on outer walls and doors. Does nothing without that mod.

placement

<placement><atWall>Preferred</atWall></placement>
<placement><weight>0.3</weight></placement>
  • atWall says how much the piece wants to touch the town wall: Forbidden, Avoid, Allowed, Preferred, StronglyPreferred or Required. Default is Allowed. When it is Allowed or missing, wallContact of the category decides.
  • weight says how often this piece is picked over others that fit. It falls back to the category weight, then 1.
  • zones, needsRoadAccess and countPerSettlement also exist here and follow the same rules as on the category.

Anchors

An anchor marks cells where something happens after the piece is built. An anchor is a legend entry with an anchor name. Its cells are drawn in the anchors grid with the entry's symbol.

  • Neighboring cells with the same symbol form one anchor area.
  • anchorKind is Connect, Fill, Object or Spawn. Default is Connect.
  • The editor shows Fill as Loot and Spawn as Pawn.
  • chance on an anchor is rolled once per anchor area.

Connect

Connect anchors tie the piece to its surroundings. The name decides what for.

Name Meaning
Wall The town wall joins the piece here. A gatehouse has two, one on each side where the wall runs in. A normal building with a Wall anchor merges into the wall.
Outside Marks the side that faces out of town. A gatehouse needs it, otherwise the generator does not know which way to turn the gate.
Anbau An annex docks here, see Annexes.
Wasser Harbor pieces only: the water side of a jetty, boat shed or fishing hut. Parts that stand over the water use bridge floor. See Settlement types in XML.

required set to true only has an effect on a Connect anchor named Wall. The piece is then only placed against the town wall.

A gatehouse, trimmed from CBF_Vanilla_Gatehouse_Wood:

<CustomBaseFramework.PieceDef>
  <defName>CBF_Vanilla_Gatehouse_Wood</defName>
  <schemaVersion>2</schemaVersion>
  <categories>
    <li>WallGateHouse</li>
    <li>CBF_Vanilla_Gatehouse</li>
  </categories>
  <type>WallPart</type>
  <legend>
    <li><symbol>7</symbol><anchor>WacheSued</anchor><anchorKind>Spawn</anchorKind><pawnList>CBF_Vanilla_Garrison</pawnList><pawnCount>1~2</pawnCount></li>
    <li><symbol>A</symbol><anchor>Outside</anchor></li>
    <li><symbol>O</symbol><thing>Wall</thing><stuff>WoodLog</stuff></li>
    <li><symbol>W</symbol><anchor>Wall</anchor></li>
    <li><symbol>g</symbol><thing>Door</thing><stuff>WoodLog</stuff></li>
  </legend>
  <things>
    <li>OOOOO</li>
    <li>O...O</li>
    <li>OOOOO</li>
    <li>.g.g.</li>
    <li>OOOOO</li>
    <li>O...O</li>
    <li>OOOOO</li>
  </things>
  <anchors>
    <li>..W..</li>
    <li>.....</li>
    <li>.....</li>
    <li>A....</li>
    <li>.....</li>
    <li>..7..</li>
    <li>..W..</li>
  </anchors>
</CustomBaseFramework.PieceDef>

The rows are shortened from the real 9 by 5 piece. The wall runs in at the north and south W. The gate passage is the row with the two doors g. A lies on the west side, so west is outside. The category WallGateHouse is what makes the generator treat the piece as a gatehouse.

If a wall piece has no Outside anchor, the field drawnOutward (North, East, South or West) names the outer side instead.

Fill

A Fill anchor places an object from an object list and fills it from a loot table.

<li><symbol>1</symbol><anchor>Kueche</anchor><anchorKind>Fill</anchorKind><objects>CBF_Vanilla_Shelf_Small</objects><lootTable>CBF_Vanilla_Loot_Kitchen</lootTable></li>
  • objects names a LootBuildingCategoryDef, an object list. One object that fits the area is placed.
  • lootTable names a LootTableDef. Without it the object stays empty, as decoration.
  • lootFremd set to true leaves the contents to the mod that brings the object. CBF adds no loot then.
  • Without an object list, a Fill anchor with a loot table puts loose loot on one of its cells.
  • Draw a placeholder under the anchor in the things grid, as the shelf a under anchor 1 in the house. The placed object takes the rotation and material of the placeholder. Without one, everything faces north.

See Loot for object lists and loot tables.

Object

An Object anchor places an object from an object list with the anchor's chance, without loot.

<li><symbol>a</symbol><anchor>Geschirr</anchor><anchorKind>Object</anchorKind><objects>CBF_MO_Tableware</objects><chance>0.8</chance><obenauf>true</obenauf></li>

obenauf set to true keeps what already stands on the cells and places the object on top, here dishes on a table. Anchors in the anchorsOver grid always behave this way.

Spawn

A Spawn anchor marks where pawns wait when the settlement is manned.

<li><symbol>8</symbol><anchor>BewohnerA</anchor><anchorKind>Spawn</anchorKind><pawnList>CBF_Vanilla_Villager</pawnList><chance>0.3</chance></li>
  • pawnList names a PawnListDef, see Pawns.
  • pawns names a single PawnKindDef instead. The editor calls it Animals.
  • pawnCount is the number of pawns, as a range. Default 1.

Roles

A legend entry can name a role instead of a fixed def. CBF takes the thing from the material list of the settlement type when the settlement is built, see Material lists.

<li><symbol>S</symbol><role>WALL</role></li>
<li><symbol>F</symbol><role>DOOR</role></li>
<li><symbol>w</symbol><role>FLOOR_INTERIOR</role></li>
  • Role names used by CBF include WALL, WALL_INNER, DOOR, GATE, PILLAR, WINDOW, FLOOR_INTERIOR, FLOOR_FINE, FLOOR_ROUGH, FLOOR_DIRT, ROOF, LIGHT, FURNITURE, CONTAINER and FENCE.
  • Cells with the role DOOR or GATE count as doors for the generator, like a thing that is a door.
  • Stone walls and floors take the stone of the map.

So one piece drawn with roles can be built in stone in one settlement type and in wood in another. The pieces shipped with CBF draw their things directly.

Things from other mods

When the mod is missing, RimWorld drops those legend entries. CBF then checks which characters have no entry left:

  • A character in the things grid without an entry, outside any anchor cell, means the building would have holes. The piece is not used at all and a warning is logged once.
  • A character without an entry in terrain, roof, things2, things3, plants, or in things under an anchor, only leaves those cells empty. The piece is still used.

Objects placed through an object list are optional. Members whose thing does not exist are dropped. If the list ends up empty, the anchor stays empty and the rest of the piece is built.

The rule for your own pieces: draw walls, doors and everything the building needs directly. Put devices, furniture and decoration that only some mods bring into an object list behind an anchor.

The annex above also shows the Anbau anchor. It lies on the west wall cell, so the annex shares its wall with the house. It could also lie one cell outside the shape, then the annex stands next to the house with its own wall.

Inheritance

  • parent names the category this one inherits from. The chain may be up to 16 deep and must not loop.
  • A field that is not set takes the value of the parent, then its parent, and so on. Most category fields are optional for this reason.
  • A piece in a child category also counts as a piece of every parent. A settlement that orders CBF_MO_Workshop can get a CBF_MO_Apothecary piece.
  • blockMax and verschmelzen are read on each category itself, not inherited.

Placement rules

Field Effect
weight How often pieces of this category are picked when several fit.
wallContact Pieces prefer to stand against the town wall. Used when the piece's atWall is Allowed or missing.
zones Inside or Outside.
needsRoadAccess Must be reachable from a road.
mauerzugang The pieces give access to the town wall, like a barracks built against it. The generator closes their open sides and counts their cells when it places wall doors.

A piece whose category has needsRoadAccess set to false and Outside in zones counts as open. It can be entered from every side, like a farm field.

Counts and uniqueness come from the settlement plan, locations from the districts, see Settlements.

Blocks

  • blockMax is the largest number of buildings of this category that join into one block, wall to wall. -1 (the default) uses the general block limit, which is 3 unless the settlement sets another.
  • verschmelzen set to true forces neighbors of this category to share walls. false forbids it. Two buildings only merge when their first category is the same.

Annexes

Field Set on Effect
anbauten the house category Which categories may dock on as annexes. Empty takes the list of the parent.
anbauChance the house category Chance per Anbau anchor that an annex is tried. Default 0.6.
anbauMax the house category Annexes per house at most. Default 2.
anbauMehrfach the annex category true allows the same annex more than once on one house.

A category becomes an annex category by being named in some anbauten list. Annex pieces without a door count as open. How annexes are placed is on Annexes.

Tips

  • Start from a shipped piece of similar size and change it. The editor's template list works the same way.
  • Keep one symbol per meaning. Legend symbols are case sensitive, so a and A are two entries.
  • Use . for empty cells, not spaces. Both work, but dots keep rows readable and equally long.
  • Give every Fill and Object anchor a rotated placeholder in things.
  • A gatehouse needs the category WallGateHouse, the type WallPart, two Wall anchors and one Outside anchor.
  • Mark a cell that belongs to the piece but should keep the map's own ground with the floor CBF_EmptyCell. It is not placed in the game.
  • Run Check in the editor after hand edits. It runs the same checks as the game on load.
  • Loading errors and skipped pieces are written to the log once per piece.
