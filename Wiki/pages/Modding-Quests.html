Modding quests

Modding

Build a settlement quest by combining a site definition, a settlement plan and the quest nodes that choose factions and control the encounter. A RuinDef can turn that settlement into a damaged or occupied location. This page documents the XML components and their relationships; Quests explains the encounters from the player’s perspective.

The two shipped quests are the working reference:

  • 1.6/Mods/MedievalOverhaul/Defs/Quests/CBF_MO_Quest_RaidedSite.xml (raided settlement)
  • 1.6/Mods/MedievalOverhaul/Defs/Quests/CBF_MO_Quest_ContestedSite.xml (settlement under attack)
  • CBF_MO_Quest_SiteParts.xml, CBF_MO_Quest_Orte.xml and CBF_MO_Quest_Ruinen.xml in the same folder

All classes are in the namespace CustomBaseFramework. You need to know how vanilla quests work: a QuestScriptDef runs quest nodes in order, nodes store values in the slate (the quest's variables, written as $name), and parts of the quest react to signals such as site.AllEnemiesDefeated.

Overview

A CBF quest site uses these defs:

Def Purpose
SitePartDef Carries CBFSiteExtension (which settlement types, which ruin) and optionally CBFOccupierExtension (which enemy factions).
WorldObjectDef The site on the world map. Uses a CBF map generator and adds the quest components.
RuinDef Optional. Damage, corpses and who garrisons the settlement.
QuestScriptDef The quest. Uses the QuestNode_CBF* nodes.

Automatic site selection uses settlement plans with non-empty siteTags, optionally filtered by planTags. The shipped village and market town plans use Dorf and Marktstadt. A fixed usable plan in CBFSiteExtension, or a plan supplied by QuestNode_CBFSite, bypasses tag selection. See SettlementPlanDef.

Site setup

WorldObjectDef

<WorldObjectDef ParentName="Site">
  <defName>CBF_MO_Quest_ContestedSite</defName>
  <label>settlement under attack</label>
  <mapGenerator>CBF_Base_Faction</mapGenerator>
  <comps>
    <li Class="CustomBaseFramework.WorldObjectCompProperties_CBFSiteGoods">
      <goodwillPer1000Silver>1.5</goodwillPer1000Silver>
      <ownedFromStart>true</ownedFromStart>
    </li>
    <li Class="CustomBaseFramework.WorldObjectCompProperties_CBFAttack" />
  </comps>
</WorldObjectDef>
  • mapGenerator must be a CBF map generator. The shipped quests use CBF_Base_Faction.
  • CBF patches WorldObjectCompProperties_Plan into the vanilla Site def. Defs with ParentName="Site" inherit it. Without it QuestNode_CBFSite logs a warning and does nothing.
  • Sites with a CBF map generator get the same background map generation on arrival as faction settlements.
  • WorldObjectCompProperties_CBFSiteGoods makes taking items cost goodwill, see WorldObjectComp_CBFOrtsgut.
  • WorldObjectCompProperties_CBFAttack is needed for QuestNode_CBFAttack, see QuestNode_CBFAttack.

CBFSiteExtension

A mod extension on the SitePartDef. It tells CBF which settlement type to build.

Field Type Default Meaning
ruin RuinDef none Ruin applied after the settlement is built. Used when QuestNode_CBFSite sets no ruin.
plan SettlementPlanDef none A fixed settlement type. Used if it is usable (loaded without errors).
planTags list of text none Settlement types whose siteTags contain one of these. Empty means any settlement type with siteTags.

CBFOccupierExtension

A mod extension on the SitePartDef. QuestNode_CBFOccupier reads it to pick the enemy faction.

Field Type Default Meaning
occupiers list of FactionDef none Factions allowed as occupier or attacker. Empty means any faction hostile to the player. 
<SitePartDef>
  <defName>CBF_MO_Quest_RaidedSite</defName>
  <requiresFaction>true</requiresFaction>
  <wantsThreatPoints>true</wantsThreatPoints>
  <minThreatPoints>300</minThreatPoints>
  <modExtensions>
    <li Class="CustomBaseFramework.CBFSiteExtension">
      <ruin>CBF_MO_Quest_Ruin_Raided</ruin>
      <planTags>
        <li>Dorf</li>
        <li>Marktstadt</li>
      </planTags>
    </li>
    <li Class="CustomBaseFramework.CBFOccupierExtension">
      <occupiers>
        <li>DankPyon_BrigandFaction</li>
      </occupiers>
    </li>
  </modExtensions>
</SitePartDef>

RuinDef and garrison

A ruin damages the finished settlement: breaches, burnt rooms, corpses. Its field occupation also decides who defends the settlement. All ruin fields are listed in RuinDef and Modding-Overview.

Value Defenders
Occupier Pawns of the site faction, bought with the points from QuestNode_CBFSite (without points, the settlement type's defenderPoints). Garrisons and pawn anchors with their own list or kind are skipped. Prisoners from prisoners are only placed in this mode, and only when the site faction is not the builder.
Builder The faction set as builder in QuestNode_CBFSite, with its normal garrison. Without a builder, the site faction.
None No defenders.

occupationChance scales the number of defenders in both Occupier and Builder mode. Default 1.

The shipped raided settlement uses Occupier. The settlement under attack uses Builder with occupationChance 0.3.

Quest nodes

QuestNode_CBFClient

Picks the quest giver. If there is no candidate, the test run fails and the quest is not offered.

A candidate faction is visible, not the player, not defeated, not hidden, not a permanent enemy, not hostile to the player, and has a living leader. Vassal colonies of the Empire mod are skipped while Leave settlements of other settlement mods alone is on in the mod settings. The faction also needs a settlement type that fits sitePart:

  • If plan is set in CBFSiteExtension, that settlement type only has to be usable.
  • Otherwise the faction needs a settlement type with siteTags that match planTags. Factions switched off in the mod settings have no settlement types.
Field Type Meaning
storeAs slate name Stores the faction leader (Pawn).
storeFactionAs slate name Stores the faction.
sitePart SitePartDef Its CBFSiteExtension decides which settlement types fit.

QuestNode_CBFOccupier

Picks the hostile faction: the occupier of a raided settlement, or the attacker of a settlement under attack. The test run fails without sitePart or without a candidate.

A candidate is not the player, not defeated, hostile to the player, listed in occupiers of the site part's CBFOccupierExtension if that list is set, and hostile to enemyOf if that is set.

Field Type Meaning
storeAs slate name Stores the faction.
storeSitePartDefsAs slate name Stores a list with sitePart as its only entry, for QuestNode_GetDefaultSitePartsParams.
sitePart SitePartDef Required.
enemyOf Faction Optional. The picked faction must be hostile to it.

QuestNode_CBFSite

Tells CBF how to build the site. Place it after QuestNode_GenerateSite.

Field Type Meaning
site Site The site.
builder Faction The settlement is built in this faction's style, independent of who owns the site.
points number Points for the defenders. 0 or less means the settlement type's own defenderPoints.
ruin RuinDef Optional. Overrides CBFSiteExtension.ruin.
plan SettlementPlanDef Optional. A fixed settlement type instead of the tag selection.

QuestNode_CBFAttack

Adds an attack on the settlement that starts when the player arrives. Needs WorldObjectCompProperties_CBFAttack on the WorldObjectDef, otherwise it logs a warning.

Field Type Meaning
site Site The site.
attacker Faction Attacking faction. Also used for the attacker corpses of the ruin.
points number Points for the attacking group.

WorldObjectCompProperties_CBFAttack has one field:

Field Type Default Meaning
approachDistance number 25 Distance in cells in front of each breach where attackers spawn.

What the attack component (WorldObjectComp_CBFAngriff) does:

  • After CBF has built the settlement, a combat group of attacker with points spawns in front of the ruin's breaches. If no cell in front is found, it spawns at the breaches. Without breaches it spawns at the map edge.
  • The defenders are the pawns CBF placed for the settlement's faction. If there are none, all humanlike pawns of that faction on the map count. Defenders without a lord that can fight get a guard duty per ward and do not flee on their own.
  • The attackers go for the defenders. Without defenders they assault the map.
  • Every 250 ticks it checks the defenders. When none is left alive, standing and on the map while hostiles are still active, it sends the site signal VerteidigerGefallen once. Listen to it as site.VerteidigerGefallen (the German name is the exact signal name).
  • If the map was generated without a CBF settlement, the attack starts at the map edge and a warning is logged.

QuestNode_CBFChoice

Sends a choice letter after the fight. The player either leaves the site to a faction or takes the loot.

Field Type Meaning
inSignalDefeated signal Sends the letter.
inSignalGone signal After inSignalDefeated: picks the loot option if no choice was made.
outSignalFaction signal Sent after "leave to faction".
outSignalLoot signal Sent after "take loot".
site Site The site.
faction Faction Receives goodwill and, on "leave to faction", the site.
lord Pawn Named in the letter. Falls back to the faction name.
goodwillFaction whole number Goodwill for "leave to faction".
goodwillLoot whole number Goodwill for "take loot".
keyLabel text key Letter label. Default CBF_Quest_Wahl_Label, argument {0} site.
keyText text key Letter text. Default CBF_Quest_Wahl_Text, arguments {0} lord, {1} faction, {2} site, {3} goodwillFaction, {4} goodwillLoot.
keyFaction text key Option button. Default CBF_Quest_Wahl_Fraktion, argument {0} goodwill.
keyLoot text key Option button. Default CBF_Quest_Wahl_Beute, argument {0} goodwill.

On "leave to faction", the site and all artificial buildings of the old site faction pass to faction. If the site has WorldObjectComp_CBFOrtsgut, its recorded goods are forbidden and belong to faction. Goods that player pawns already carry are charged at once. The letter cannot be dismissed with a right click.

WorldObjectComp_CBFOrtsgut

Charges goodwill for goods the player takes from the site. This stops the player from freeing a settlement and then looting its owner. It is added with WorldObjectCompProperties_CBFSiteGoods.

Field Type Default Meaning
goodwillPer1000Silver number 1.5 Goodwill lost per 1000 silver of market value. 0 turns the cost off.
ownedFromStart bool false The site faction owns the goods from map generation on. Otherwise an owner is only set by QuestNode_CBFChoice.
  • At map generation it records every haulable item on the map. Pawns, corpses and chunks are left out. Stacks split from a recorded item are recorded too.
  • Nothing is charged while there is no owner.
  • A recorded item counts as taken when a player pawn puts it into its inventory, carries it, equips it or wears it. When only part of a stack is merged into a carried stack, only that part is charged.
  • A spawned thing of the owner that changes to the player faction is charged at its market value.
  • Fractions add up. Goodwill drops in whole points with the history event CBF_Quest_SiteGoodsTaken.
  • The inspect string of the site shows the owner with the keys CBF_Quest_Ortsgut_Inspect or CBF_Quest_Ortsgut_Inspect_Eigen.

CBFRewardExtension

A mod extension on the QuestScriptDef. It filters the item rewards generated for this quest, so that a medieval quest does not pay in plasteel.

Field Type Default Meaning
maxTechLevel TechLevel Medieval Highest allowed tech level.
forbiddenThings list of ThingDef none Always excluded.

The tech level of a thing is the highest of its own techLevel, its research prerequisites and the research of its recipeMaker. Things with a power comp count as at least Industrial. Excluded things are added to the reward's disallowed things and removed from the market value fillers while rewards are generated.

Shortened from CBF_MO_Quest_ContestedSite.xml:

<QuestScriptDef>
  <defName>CBF_MO_Quest_ContestedSite</defName>
  <modExtensions>
    <li Class="CustomBaseFramework.CBFRewardExtension">
      <maxTechLevel>Medieval</maxTechLevel>
      <forbiddenThings>
        <li>Plasteel</li>
        <li>ComponentIndustrial</li>
        <li MayRequire="Ludeon.RimWorld.Biotech">PowerfocusChip</li>
      </forbiddenThings>
    </li>
  </modExtensions>
</QuestScriptDef>

Example: contested settlement

Trimmed from CBF_MO_Quest_ContestedSite.xml. Name rules, description rules, the timeout, the "player left" branch and the reward branch are left out.

<QuestScriptDef>
  <defName>CBF_MO_Quest_ContestedSite</defName>
  <rootSelectionWeight>1.0</rootSelectionWeight>
  <rootMinPoints>300</rootMinPoints>
  <root Class="QuestNode_Sequence">
    <nodes>
      <li Class="QuestNode_GetMap" />
      <li Class="CustomBaseFramework.QuestNode_CBFClient">
        <storeAs>asker</storeAs>
        <storeFactionAs>askerFaction</storeFactionAs>
        <sitePart>CBF_MO_Quest_ContestedSite</sitePart>
      </li>
      <li Class="QuestNode_GetSiteTile">
        <storeAs>siteTile</storeAs>
        <preferCloserTiles>true</preferCloserTiles>
      </li>
      <li Class="CustomBaseFramework.QuestNode_CBFOccupier">
        <storeAs>angreiferFaction</storeAs>
        <storeSitePartDefsAs>sitePartDefs</storeSitePartDefsAs>
        <sitePart>CBF_MO_Quest_ContestedSite</sitePart>
        <enemyOf>$askerFaction</enemyOf>
      </li>
      <li Class="QuestNode_GetDefaultSitePartsParams">
        <tile>$siteTile</tile>
        <faction>$askerFaction</faction>
        <sitePartDefs>$sitePartDefs</sitePartDefs>
        <storeSitePartsParamsAs>sitePartsParams</storeSitePartsParamsAs>
      </li>
      <li Class="QuestNode_GetSiteThreatPoints">
        <storeAs>sitePoints</storeAs>
        <sitePartsParams>$sitePartsParams</sitePartsParams>
      </li>
      <li Class="QuestNode_Multiply">
        <value1>$sitePoints</value1>
        <value2>3</value2>
        <storeAs>angreiferPunkte</storeAs>
      </li>
      <li Class="QuestNode_GenerateSite">
        <sitePartsParams>$sitePartsParams</sitePartsParams>
        <faction>$askerFaction</faction>
        <tile>$siteTile</tile>
        <worldObjectDef>CBF_MO_Quest_ContestedSite</worldObjectDef>
        <storeAs>site</storeAs>
      </li>
      <li Class="CustomBaseFramework.QuestNode_CBFSite">
        <site>$site</site>
        <builder>$askerFaction</builder>
        <points>$sitePoints</points>
      </li>
      <li Class="CustomBaseFramework.QuestNode_CBFAttack">
        <site>$site</site>
        <attacker>$angreiferFaction</attacker>
        <points>$angreiferPunkte</points>
      </li>
      <li Class="QuestNode_SpawnWorldObjects">
        <worldObjects>$site</worldObjects>
      </li>
      <li Class="QuestNode_Signal">
        <inSignal>site.VerteidigerGefallen</inSignal>
        <node Class="QuestNode_End">
          <outcome>Fail</outcome>
        </node>
      </li>
      <li Class="QuestNode_End">
        <inSignal>site.AllEnemiesDefeated</inSignal>
        <outcome>Success</outcome>
      </li>
    </nodes>
  </root>
</QuestScriptDef>

Step by step:

  1. QuestNode_CBFClient picks a friendly faction that has a village or market town settlement type (the planTags of the site part). It stores the faction and its leader.
  2. QuestNode_CBFOccupier picks a brigand faction that is hostile to the player and to the quest giver.
  3. The site belongs to the quest giver (faction is $askerFaction). The attackers get three times the site points.
  4. QuestNode_CBFSite builds the settlement in the quest giver's style. The site part's ruin CBF_MO_Quest_Ruin_Battle uses occupation Builder, so the defenders are the quest giver's soldiers.
  5. QuestNode_CBFAttack spawns the attackers in front of the breaches once the settlement is built.
  6. site.VerteidigerGefallen fails the quest. site.AllEnemiesDefeated completes it.

Example: the choice

From CBF_MO_Quest_RaidedSite.xml. Here the site belongs to the occupier (QuestNode_GenerateSite with $siteFaction). QuestNode_CBFSite sets builder to the quest giver and points to 1.5 times the site points.

<li Class="CustomBaseFramework.QuestNode_CBFChoice">
  <inSignalDefeated>site.AllEnemiesDefeated</inSignalDefeated>
  <inSignalGone>site.Destroyed</inSignalGone>
  <outSignalFaction>WahlFraktion</outSignalFaction>
  <outSignalLoot>WahlBeute</outSignalLoot>
  <site>$site</site>
  <faction>$askerFaction</faction>
  <lord>$asker</lord>
  <goodwillFaction>20</goodwillFaction>
  <goodwillLoot>3</goodwillLoot>
</li>
<li Class="QuestNode_End">
  <inSignal>WahlFraktion</inSignal>
  <outcome>Success</outcome>
</li>
<li Class="QuestNode_End">
  <inSignal>WahlBeute</inSignal>
  <outcome>Success</outcome>
</li>

The signal names WahlFraktion and WahlBeute are chosen by the quest. Any name works as long as the QuestNode_End nodes use the same one.

The WorldObjectDef of this site has WorldObjectCompProperties_CBFSiteGoods without ownedFromStart. Taking goods is free until the player picks "leave to faction".

Debug actions

With development mode on, the debug menu has a group "CBF Quests". These actions work while a map is open:

  • Enter raided settlement: generates the map of a site that has WorldObjectComp_CBFOrtsgut and moves the free colonists of the current map there.
  • Defeat occupiers: kills all pawns hostile to the player on the current map.
  • Log raided settlement: writes site, settlement type, builder, ruin, points and recorded goods to the log.
  • Carry settlement item: a free colonist picks up the most valuable recorded item, and the goodwill change is logged.
