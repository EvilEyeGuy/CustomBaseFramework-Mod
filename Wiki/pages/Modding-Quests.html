Modding quests

CBF has quest nodes and components to send the player to a CBF settlement that is built for a quest. The two shipped quests use them, see Quests. Their files are the reference:

  • 1.6/Mods/MedievalOverhaul/Defs/Quests/CBF_MO_Quest_UeberfallenerOrt.xml (raided settlement)
  • 1.6/Mods/MedievalOverhaul/Defs/Quests/CBF_MO_Quest_UmkaempfterOrt.xml (contested settlement)
  • CBF_MO_Quest_SiteParts.xml, CBF_MO_Quest_Orte.xml and CBF_MO_Quest_Ruinen.xml in the same folder

All classes are in the namespace CustomBaseFramework.

Overview

A CBF quest site needs four defs:

Def Purpose
SitePartDef Carries CBFOrtExtension (which plans, which ruin) and optionally CBFBesatzerExtension (which enemy factions).
WorldObjectDef The site. Uses a CBF map generator and adds the quest components.
RuinDef Optional. Damage, corpses and who garrisons the settlement.
QuestScriptDef The quest. Uses the QuestNode_CBF* nodes.

The settlement plan must have siteTags, see SettlementPlanDef. Plans without siteTags are never used for sites.

Site setup

WorldObjectDef

xml <WorldObjectDef ParentName="Site"> <defName>CBF_MO_Quest_UmkaempfterOrt</defName> <label>settlement under attack</label> <mapGenerator>CBF_Base_Faction</mapGenerator> <comps> <li Class="CustomBaseFramework.WorldObjectCompProperties_CBFOrtsgut"> <ansehenJe1000Silber>1.5</ansehenJe1000Silber> <vonAnfangEigen>true</vonAnfangEigen> </li> <li Class="CustomBaseFramework.WorldObjectCompProperties_CBFAngriff" /> </comps> </WorldObjectDef>

  • mapGenerator must be a CBF map generator. The shipped quests use CBF_Base_Faction.
  • CBF patches WorldObjectCompProperties_Plan into the vanilla Site def. Defs with ParentName="Site" inherit it. Without it QuestNode_CBFOrt logs a warning and does nothing.
  • Sites with a CBF map generator get the background map generation on arrival like faction settlements.

CBFOrtExtension

On the SitePartDef.

Field Type Default Meaning
ruin RuinDef none Ruin applied after the settlement is built. Used when QuestNode_CBFOrt sets no ruin.
plan SettlementPlanDef none A fixed plan. Used if it is usable.
planTags list of text none Plans whose siteTags contain one of these. Empty means any plan with siteTags.

CBFBesatzerExtension

On the SitePartDef. Read by QuestNode_CBFBesatzer.

Field Type Default Meaning
besatzer list of FactionDef none Factions allowed as occupier or attacker. Empty means any faction hostile to the player.

xml <SitePartDef> <defName>CBF_MO_Quest_UeberfallenerOrt</defName> <requiresFaction>true</requiresFaction> <wantsThreatPoints>true</wantsThreatPoints> <minThreatPoints>300</minThreatPoints> <modExtensions> <li Class="CustomBaseFramework.CBFOrtExtension"> <ruin>CBF_MO_Quest_Ruin_Ueberfallen</ruin> <planTags> <li>Dorf</li> <li>Marktstadt</li> </planTags> </li> <li Class="CustomBaseFramework.CBFBesatzerExtension"> <besatzer> <li>DankPyon_BrigandFaction</li> </besatzer> </li> </modExtensions> </SitePartDef>

RuinDef and garrison

The RuinDef field besatzung decides who garrisons the built settlement:

Value Garrison
Besatzer The site faction, sized by the points from QuestNode_CBFOrt. Prisoners from gefangene are only placed in this mode.
Bauherr The faction set as bauherr, scaled by besatzungAnteil.
Keine No garrison.

The shipped raided settlement uses Besatzer. The contested settlement uses Bauherr with besatzungAnteil 0.3.

Quest nodes

QuestNode_CBFAuftraggeber

Picks the quest giver. Fails the test run if there is no candidate, so the quest is not offered.

A candidate faction is visible, not the player, not defeated, not hidden, not a permanent enemy, not hostile to the player and has a living leader. Empire vassal colonies are skipped. It also needs a plan that fits sitePart:

  • With plan set in CBFOrtExtension, that plan only has to be usable.
  • Otherwise the faction needs a plan with siteTags that match planTags. Factions switched off in the mod settings have no plans.
Field Type Meaning
storeAs slate name Stores the faction leader (Pawn).
storeFactionAs slate name Stores the faction.
sitePart SitePartDef Its CBFOrtExtension decides which plans fit.

QuestNode_CBFBesatzer

Picks the hostile faction. Fails the test run without sitePart or without a candidate.

A candidate is not the player, not defeated, hostile to the player, listed in CBFBesatzerExtension.besatzer if that list is set, and hostile to feindVon if set.

Field Type Meaning
storeAs slate name Stores the faction.
storeSitePartDefsAs slate name Stores a list with sitePart as its only entry, for QuestNode_GetDefaultSitePartsParams.
sitePart SitePartDef Required.
feindVon Faction Optional. The picked faction must be hostile to it.

QuestNode_CBFOrt

Tells CBF how to build the site. Place it after QuestNode_GenerateSite.

Field Type Meaning
site Site The site.
bauherr Faction Builder. The settlement is built in this faction's style, independent of the site faction.
punkte number Garrison points. 0 or less means CBF's normal garrison.
ruin RuinDef Optional. Overrides CBFOrtExtension.ruin.
plan SettlementPlanDef Optional. A fixed plan instead of the tag selection.

QuestNode_CBFAngriff

Adds an attack on the settlement. Needs WorldObjectCompProperties_CBFAngriff on the WorldObjectDef, otherwise it logs a warning.

Field Type Meaning
site Site The site.
angreifer Faction Attacking faction. Also used for the attacker corpses of the ruin.
punkte number Points for the attacking combat group.

WorldObjectCompProperties_CBFAngriff has one field:

Field Type Default Meaning
ansatzAbstand number 25 Distance in cells in front of each breach where attackers spawn.

Behaviour of WorldObjectComp_CBFAngriff:

  • After CBF has built the settlement, a combat group of angreifer with punkte spawns in front of the breaches of the ruin. If no cell in front is found, it spawns at the breaches. Without breaches it spawns at the map edge.
  • Defenders are the garrison pawns CBF placed for the settlement faction. Those without a lord and able to fight get a guard duty per ward and do not flee on their own.
  • The attackers go for the defenders. Without defenders they assault the map.
  • Every 250 ticks it checks the defenders. When none is on the map, alive and standing while hostiles are still active, it sends the site signal VerteidigerGefallen once. Listen to it as site.VerteidigerGefallen.
  • If the map was generated without a CBF settlement, the attack starts at the map edge and a warning is logged.

QuestNode_CBFWahl

A choice letter after the fight: leave the site to a faction or take the loot.

Field Type Meaning
inSignalBesiegt signal Sends the letter.
inSignalWeg signal After inSignalBesiegt: picks the loot option if no choice was made.
outSignalFraktion signal Sent after "leave to faction".
outSignalBeute signal Sent after "take loot".
site Site The site.
fraktion Faction Receives goodwill and, on "leave to faction", the site.
lord Pawn Named in the letter. Falls back to the faction name.
ansehenFraktion whole number Goodwill for "leave to faction".
ansehenBeute whole number Goodwill for "take loot".
schluesselLabel text key Letter label. Default CBF_Quest_Wahl_Label, argument {0} site.
schluesselText text key Letter text. Default CBF_Quest_Wahl_Text, arguments {0} lord, {1} faction, {2} site, {3} ansehenFraktion, {4} ansehenBeute.
schluesselFraktion text key Option button. Default CBF_Quest_Wahl_Fraktion, argument {0} goodwill.
schluesselBeute text key Option button. Default CBF_Quest_Wahl_Beute, argument {0} goodwill.

On "leave to faction" the site and all artificial buildings of the old site faction pass to fraktion. If the site has WorldObjectComp_CBFOrtsgut, its goods are forbidden and belong to fraktion. Goods already carried by player pawns are charged at once. The letter cannot be dismissed with a right click.

WorldObjectComp_CBFOrtsgut

Charges goodwill for goods the player takes from the site. Added with WorldObjectCompProperties_CBFOrtsgut.

Field Type Default Meaning
ansehenJe1000Silber number 1.5 Goodwill lost per 1000 silver of market value. 0 turns the cost off.
vonAnfangEigen bool false The site faction owns the goods from map generation on. Otherwise an owner is only set by QuestNode_CBFWahl.
  • At map generation it records every haulable item on the map. Pawns, corpses and chunks are left out. Stacks split from a recorded item are recorded too.
  • Nothing is charged while there is no owner.
  • A recorded item counts as taken when a player pawn gets it into inventory, carry slot, equipment or apparel. Partial stack merges are charged by count.
  • A spawned thing of the owner that changes to the player faction is charged at its market value.
  • Fractions add up. Goodwill drops in whole points with the history event CBF_Quest_OrtsgutGenommen.
  • The inspect string shows the owner with the keys CBF_Quest_Ortsgut_Inspect or CBF_Quest_Ortsgut_Inspect_Eigen.

CBFBelohnungExtension

On the QuestScriptDef. Filters item rewards generated for this quest.

Field Type Default Meaning
hoechsteTechstufe TechLevel Medieval Highest allowed tech level.
verboteneDinge list of ThingDef none Always excluded.

The tech level of a thing is the highest of its own techLevel, its research prerequisites and the research of its recipeMaker. Things with a power comp count as at least Industrial. Excluded things are added to the reward's disallowed things and removed from the market value fillers while rewards are generated.

xml <QuestScriptDef> <defName>CBF_MO_Quest_UmkaempfterOrt</defName> <modExtensions> <li Class="CustomBaseFramework.CBFBelohnungExtension"> <hoechsteTechstufe>Medieval</hoechsteTechstufe> <verboteneDinge> <li>Plasteel</li> <li>ComponentIndustrial</li> <li MayRequire="Ludeon.RimWorld.Biotech">PowerfocusChip</li> </verboteneDinge> </li> </modExtensions> </QuestScriptDef>

Example: contested settlement

Trimmed from CBF_MO_Quest_UmkaempfterOrt.xml. Name rules, description rules, the timeout and the leave and reward branches are left out.

xml <QuestScriptDef> <defName>CBF_MO_Quest_UmkaempfterOrt</defName> <rootSelectionWeight>1.0</rootSelectionWeight> <rootMinPoints>300</rootMinPoints> <root Class="QuestNode_Sequence"> <nodes> <li Class="QuestNode_GetMap" /> <li Class="CustomBaseFramework.QuestNode_CBFAuftraggeber"> <storeAs>asker</storeAs> <storeFactionAs>askerFaction</storeFactionAs> <sitePart>CBF_MO_Quest_UmkaempfterOrt</sitePart> </li> <li Class="QuestNode_GetSiteTile"> <storeAs>siteTile</storeAs> <preferCloserTiles>true</preferCloserTiles> </li> <li Class="CustomBaseFramework.QuestNode_CBFBesatzer"> <storeAs>angreiferFaction</storeAs> <storeSitePartDefsAs>sitePartDefs</storeSitePartDefsAs> <sitePart>CBF_MO_Quest_UmkaempfterOrt</sitePart> <feindVon>$askerFaction</feindVon> </li> <li Class="QuestNode_GetDefaultSitePartsParams"> <tile>$siteTile</tile> <faction>$askerFaction</faction> <sitePartDefs>$sitePartDefs</sitePartDefs> <storeSitePartsParamsAs>sitePartsParams</storeSitePartsParamsAs> </li> <li Class="QuestNode_GetSiteThreatPoints"> <storeAs>sitePoints</storeAs> <sitePartsParams>$sitePartsParams</sitePartsParams> </li> <li Class="QuestNode_Multiply"> <value1>$sitePoints</value1> <value2>3</value2> <storeAs>angreiferPunkte</storeAs> </li> <li Class="QuestNode_GenerateSite"> <sitePartsParams>$sitePartsParams</sitePartsParams> <faction>$askerFaction</faction> <tile>$siteTile</tile> <worldObjectDef>CBF_MO_Quest_UmkaempfterOrt</worldObjectDef> <storeAs>site</storeAs> </li> <li Class="CustomBaseFramework.QuestNode_CBFOrt"> <site>$site</site> <bauherr>$askerFaction</bauherr> <punkte>$sitePoints</punkte> </li> <li Class="CustomBaseFramework.QuestNode_CBFAngriff"> <site>$site</site> <angreifer>$angreiferFaction</angreifer> <punkte>$angreiferPunkte</punkte> </li> <li Class="QuestNode_SpawnWorldObjects"> <worldObjects>$site</worldObjects> </li> <li Class="QuestNode_Signal"> <inSignal>site.VerteidigerGefallen</inSignal> <node Class="QuestNode_End"> <outcome>Fail</outcome> </node> </li> <li Class="QuestNode_End"> <inSignal>site.AllEnemiesDefeated</inSignal> <outcome>Success</outcome> </li> </nodes> </root> </QuestScriptDef>

Step by step:

  1. QuestNode_CBFAuftraggeber picks a friendly faction that has a village or market town plan (planTags of the site part) and stores it with its leader.
  2. QuestNode_CBFBesatzer picks a brigand faction hostile to the player and to the quest giver.
  3. The site belongs to the quest giver (faction is $askerFaction). The attackers get three times the site points.
  4. QuestNode_CBFOrt builds the settlement in the quest giver's style. The site part's ruin CBF_MO_Quest_Ruin_Schlacht uses besatzung Bauherr, so the defenders are the quest giver's soldiers.
  5. QuestNode_CBFAngriff spawns the attackers in front of the breaches once the settlement is built.
  6. site.VerteidigerGefallen fails the quest, site.AllEnemiesDefeated completes it.

Example: the choice

From CBF_MO_Quest_UeberfallenerOrt.xml. Here the site belongs to the occupier (QuestNode_GenerateSite with $siteFaction), QuestNode_CBFOrt sets bauherr to the quest giver and punkte to 1.5 times the site points.

```xml

  • site.AllEnemiesDefeated site.Destroyed WahlFraktion WahlBeute $site $askerFaction $asker 20 3
  • WahlFraktion Success
  • WahlBeute Success

    • ```

    The WorldObjectDef of this site has WorldObjectCompProperties_CBFOrtsgut without vonAnfangEigen. Taking goods is free until the player picks "leave to faction".

    Debug actions

    Under "CBF Quests" in the debug menu, while on a map:

    • Enter raided settlement: generates the map of a site with WorldObjectComp_CBFOrtsgut and moves the free colonists there.
    • Defeat occupiers: kills all pawns hostile to the player on the current map.
    • Log raided settlement: writes site, plan, builder, ruin, points and recorded goods to the log.
    • Carry settlement item: a free colonist picks up the most valuable recorded item and the goodwill change is logged.
