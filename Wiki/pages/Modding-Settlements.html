Writing a settlement type in XML

Modding

This page is for modders who write settlement types by hand. The in-game editor writes the same XML, see Settlements. Every node on this page exists in the code. The full list is in the field reference, linked at the end.

What a settlement type is

A settlement type is a CustomBaseFramework.SettlementPlanDef. It does not contain a map. It is a building program: which wards the place has, which walls, towers and gates protect them, which buildings go where, and which fields and pens lie around it.

When a caravan or raid first reaches a base, the generator plans the settlement on the real map of that tile:

  1. It picks one settlement type for the faction.
  2. It lays out the wards as rings: the town in the middle, the suburb around it, the countryside outside.
  3. It builds the walls, places towers and gatehouses, and runs the main road and lanes through the gates.
  4. It splits each ward into districts and places the buildings each district asks for.
  5. It adds fields next to farmhouses and pens in the countryside.
  6. It fills every planned spot with a piece (a PieceDef, see Pieces) and spawns the garrison.

The settlement type decides what is asked for. The pieces decide what each building looks like.

Minimal example

The shortest settlement type that loads without errors and is actually used:

<Defs>
  <CustomBaseFramework.SettlementPlanDef>
    <defName>MyMod_Plan_Hamlet</defName>
    <label>hamlet</label>
    <kind>Modernestadt</kind>
    <styles>
      <li>CBF_ModernVanilla</li>
    </styles>
    <techLevels>
      <li>Industrial</li>
    </techLevels>
    <fuerAlleFraktionen>true</fuerAlleFraktionen>
    <wards>
      <li>
        <art>Stadt</art>
        <districts>
          <li>
            <entries>
              <li><tag>CBF_Vanilla_HouseSmall</tag><count>6~10</count><filler>true</filler></li>
            </entries>
          </li>
        </districts>
      </li>
    </wards>
  </CustomBaseFramework.SettlementPlanDef>
</Defs>
  • kind is set to Modernestadt because the default kind, Mittelalterstadt, needs a wall on the town ward. Without one the planner stops with "The fortified city requires a wall template".
  • styles names one of the shipped styles.
  • materialList names a material list; without one the plan is not used.
  • techLevels together with fuerAlleFraktionen makes the plan available to every industrial faction that has no plans of its own. Without faction settings the plan is only used for places that have no faction.
  • The load check needs at least one building entry, a mapSize of 150 or more (default 175) and road widths within the limit of the kind.
  • There is no garrison, so the defenders come from defenderPoints (default 180 to 420).

Header fields

From CBF_Plan_Village_Neu (Medieval Overhaul village), trimmed:

<CustomBaseFramework.SettlementPlanDef MayRequire="DankPyon.Medieval.Overhaul">
  <defName>CBF_Plan_Village_Neu</defName>
  <label>village (MO)</label>
  <kind>Mittelalterstadt</kind>
  <styles>
    <li>Rustical</li>
    <li>Standard</li>
  </styles>
  <coreSize>50~60</coreSize>
  <mapSize>200</mapSize>
  <factionTags>
    <li>DankPyon_NobleHouseSavage</li>
    <li>DankPyon_NobleHouseCivil</li>
  </factionTags>
  <fuerAlleFraktionen>true</fuerAlleFraktionen>
  <techLevels>
    <li>Medieval</li>
  </techLevels>
  <anteil>80</anteil>
  <worldTexture>World/WorldObjects/CBF/CBF_VillagePalisade</worldTexture>
  <wdStufe>1</wdStufe>
</CustomBaseFramework.SettlementPlanDef>
Node Editor name What it does Default
defName Unique name. Saved on the world object, so do not rename it after release. required
label Label Name players see on the world map. none
kind Settlement kind Mittelalterstadt (medieval, town ward needs a wall) or Modernestadt (modern, walls optional, roads up to 6 wide). Lager and Verlies exist but are never picked in the current version. Mittelalterstadt
styles Styles used to pick the wall profile. They do not filter which pieces are used. none
materialList Material list Required. The material list for walls, doors, gates, fences, roads and roofs the generator builds itself. none
coreSize Core size Smallest edge length of the settlement. If the buildings need more room the settlement grows, up to what the map allows. 66~74
mapSize Map size Edge length of the map this settlement asks for. The larger of this and the world setting is used. Below 150 is a load error. 175
factionTags Factions FactionDef defNames or faction categoryTag values that get this plan. none
excludeFactions Excluded factions FactionDef defNames that never get this plan. none
techLevels Tech levels Tech levels this plan fits. Only used together with fuerAlleFraktionen. none
fuerAlleFraktionen For every faction of these levels Offers the plan to every faction whose tech level is in techLevels, unless that faction has plans of its own. false
anteil Weight Chance against the other plans a faction can get. 0 counts as 1. 0
worldTexture World map icon Texture path of the world map icon, tinted in the faction color. none
wdStufe WD tier World Domination tier this plan stands for, 0 to 4, as a number or a range like 2~3. 0 means no tier. See Compatibility. 0
requiredMods Needs these mods Read by the editor only. When the editor saves the plan, it writes these mods and the ones it detects into MayRequire on the def node. It does not stop a hand-written def from loading. none
siteTags Plans with site tags are the only ones used for quest sites. Leave it empty for faction bases. none

MayRequire

MayRequire is RimWorld's own attribute. On the def node it skips the whole plan when the mod is missing. On a list item it skips only that item:

<plants>
  <li MayRequire="DankPyon.Medieval.Overhaul">DankPyon_Plant_Wheat</li>
  <li>Plant_Corn</li>
</plants>

Put MayRequire on the def node whenever the plan names pieces, categories or pawn lists from another mod. requiredMods alone does not protect a hand-written plan.

Wards

A ward is one ring of the settlement. There are three kinds, set with art:

art Editor name Layer Notes
Stadt Town inner Required. In a medieval plan it must have walls.
Vorstadt Suburb middle Optional. Without walls it is an open suburb. Without the ward there is no suburb.
Umland Countryside outer Optional. Never walled. Pens are only placed here.

Write each kind once. The enum also lists Burg, but the planner has no layer of its own for it; do not use it.

From CBF_Plan_FortressCity_Neu, the town ward, trimmed:

<wards>
  <li>
    <art>Stadt</art>
    <label>Old town</label>
    <roads>
      <li>DankPyon_Floor_Cobblestone_Granite</li>
    </roads>
    <walls>
      <li><piece>TownWall_1x5</piece><weight>0.75</weight></li>
      <li><piece>CBF_MO_Stadtmauer_1x5_Scharte</piece><weight>0.25</weight></li>
    </walls>
    <emplacements>
      <li><tag>CBF_MO_Festungsturm</tag><count>4~6</count></li>
    </emplacements>
    <gatehouses>
      <li><tag>CBF_MO_Festungstor</tag><count>1~2</count></li>
    </gatehouses>
    <garrison>
      <li><list>CBF_MO_Garnison_Wehrgang</list><count>16~21</count><posten>Wehrgang</posten></li>
      <li><list>CBF_MO_Garnison_Tor</list><count>5~8</count><posten>Tor</posten></li>
      <li><list>CBF_MO_Garnison_Innen</list><count>8~13</count><posten>Innen</posten></li>
    </garrison>
    <districts>
      ...
    </districts>
  </li>
</wards>

The shipped file has no label line; it is added here to show the node.

Node Editor name What it does Default
art Kind Ward kind, see above. Stadt
label Label Name shown for the ward. Empty uses the kind name. none
name Name Replaced by the kind at load. Use label instead. Stadt
walls Walls Wall pieces of this ring, see below. none
emplacements Defensive positions Towers and other works on the wall. none
gatehouses Gatehouses Pieces built where a road crosses the wall. Empty takes the gatehouse of the wall profile. none
tor Gate ThingDef that closes the gate passages. Empty uses the gate of the material list. none
garrison Garrison Defenders of this ward, see below. none
ground Ground TerrainDefs for the open ground between the houses. Empty keeps the map terrain. none
roads Paths TerrainDefs for lanes, squares and gate passages. Empty uses the road of the material list. none
roadEdges Kerb TerrainDefs for the road edge. none
abstand Gap between buildings in this ward, as a range. The planner uses the lower value, 0 to 4. 0~0
raeumen false leaves some plants and trees standing on open ground. true
size, wallDepth Size, Wall thickness Kept for the editor. The planner sizes a ward from its buildings and takes the wall thickness from the wall pieces. 1, 0

Walls, emplacements and gatehouses

All three are lists of wall entries. An entry is either plain text or a node with fields:

<walls>
  <li MayRequire="DankPyon.Medieval.Overhaul">Palisade</li>
  <li><piece>CBF_MO_Stadtmauer_Scharte</piece><weight>0.25</weight></li>
</walls>
<emplacements>
  <li><tag>CBF_MO_Palisadenturm</tag><count>1~2</count></li>
</emplacements>
<gatehouses>
  <li><piece>CBF_MO_Torhaus</piece></li>
</gatehouses>
  • walls: the pieces the wall is built from. The first entry is plain text, the second names one piece with piece and a weight, so it makes up about a fifth of the wall.
  • emplacements: towers and other pieces set into the wall. Here one or two pieces from the category CBF_MO_Palisadenturm, picked with tag.
  • gatehouses: the pieces placed where roads cross the wall. Here always the piece CBF_MO_Torhaus.
Node What it does Default
plain text A PieceDef or PieceCategoryDef name. CBF looks for a piece first, then a category.
piece One PieceDef. none
tag A PieceCategoryDef. Every non-template piece in it can be used. none
weight Share of this entry. For walls it sets how often each piece appears along the wall. 1
count For emplacements and gatehouses: how many. 0~0 lets the planner place as many as the wall needs. 0~0
  • A wall piece must be one cell wide in one direction. Its length in the other direction is the wall thickness: 1 is a palisade, 3 a wall with a walkway, 5 a broad fortress wall.
  • Use pieces of the same thickness within one ward. The thickness comes from the wall pieces, not from any wallDepth node.
  • Tower sizes are read from square pieces with an odd edge length.

Garrison

Node What it does Default
list A PawnListDef, see Pawns. A missing list leaves the entry empty and logs a warning. none
count How many pawns from this list. 1~1
posten Post: Innen (inside), Wehrgang (on the wall walkway) or Tor (at the gates). Innen

A ward with a garrison uses only its own entries. A ward without one takes its share of the plan's defenderPoints. defendersOnWall (default 0.25) sets how many of those point-based defenders stand on the wall.

Districts and building entries

A district is a group of buildings that stay together. Each ward has one or more districts.

From CBF_Plan_FortressCity_Neu, town ward:

<districts>
  <li>
    <name>Burg</name>
    <prefCenter>1</prefCenter>
    <entries>
      <li><tag>CBF_MO_Festungsbergfried</tag><count>1~1</count><unique>true</unique></li>
      <li><tag>CBF_MO_Kaserne</tag><count>2~2</count></li>
      <li><piece>CBF_MO_Verlies</piece><count>1~2</count></li>
    </entries>
  </li>
  <li>
    <name>Zentrum</name>
    <entries>
      <li><tag>CBF_MO_Gasthaus</tag><count>1~1</count></li>
      <li><tag>CBF_MO_Kirche</tag><count>1~1</count></li>
      <li><tag>CBF_MO_Buergerhaus</tag><count>6~14</count><filler>true</filler></li>
      <li><tag>CBF_MO_Lueckenhof</tag><count>0~6</count><filler>true</filler></li>
    </entries>
  </li>
</districts>

The prefCenter line is added for this page; the shipped plan leaves the location to the planner.

District nodes

Node Editor name What it does Default
name Name Internal name. Must be unique across the whole plan, a duplicate logs a warning. Fields and pens use it to find their buildings. Default
label Label Display name. none
entries Buildings The building entries. none
prefCenter Toward the center Pull toward the center of the ward. 0
prefGate Toward the gate Pull toward the gates. 0
prefWall Toward the wall Pull toward the wall. 0
prefMain Along the main road Pull toward the main road. 0
fields, pens Fields, Pens See the next section. none

The four location values are weighed against each other, so 1 and 0 means the same as 0.5 and 0. When all four are 0, the district starts as far as possible from the districts already placed.

Building entries

Node Editor name What it does Default
tag Category A PieceCategoryDef. The planner picks pieces from this category. none
piece One specific PieceDef. none
count Count How many, as a range. More than 150 is cut to 150. 1~1
unique Only once Sets the count to exactly 1. false
filler Filler After the fixed buildings are placed, filler entries fill the free space until the target built share is reached. They may go above their maximum. A filler counts as missing only below half its minimum. false
weight Weight Only on piece entries. Changes how often that piece is chosen wherever its category is drawn in this plan. 0 turns the piece off. On tag entries it has no effect. 1
lootTable A LootTableDef. Used for loot spots in these pieces that name no table of their own. Only on tag entries. A missing table logs a warning. none
  • Name either tag or piece. With both, the piece wins and a warning is logged. With neither, the entry is skipped.
  • Use tag for anything that should vary. Use piece for one building that must appear as drawn, such as a keep or a dungeon.
  • The minimum of an entry is a wish, not a guarantee. If the space runs out, the planner reports what it could not place.

Fields and pens

Fields and pens belong to a district in the suburb or countryside ward. From CBF_Plan_Village_Neu:

<li>
  <art>Umland</art>
  <districts>
    <li>
      <name>Muehle</name>
      <fields>
        <li>
          <count>2~3</count>
          <fence>false</fence>
          <plants>
            <li MayRequire="DankPyon.Medieval.Overhaul">DankPyon_Plant_Wheat</li>
          </plants>
          <tags>
            <li>CBF_MO_Muehle</li>
          </tags>
        </li>
      </fields>
      <entries>
        <li><tag>CBF_MO_Muehle</tag><count>1~1</count></li>
      </entries>
    </li>
    <li>
      <name>Weide</name>
      <pens>
        <li>
          <count>1~1</count>
          <herd>2~5</herd>
          <pawns>Hardanimals_1</pawns>
          <terrain>Soil</terrain>
          <plants>
            <li>Plant_Haygrass</li>
          </plants>
        </li>
      </pens>
      <entries>
        <li><tag>CBF_MO_Scheune</tag><count>1~1</count></li>
      </entries>
    </li>
  </districts>
</li>

Field nodes

Fields are read from the Vorstadt and Umland wards. Fields in the town ward are ignored.

Node Editor name What it does Default
count Count How many fields this entry adds to the ward. 1~1
tags Categories (Farmsteads) Categories whose buildings get a field next to them. Empty in a district takes the categories of the district's entries. none
plants Plants ThingDefs of the crops. none
crops Crop list A CropListDef with weighted plants. Used instead of plants when set, see Loot. none
fence Fence around the field. false
weight Weight Chance of this field kind when a district has several. 1

The field needs a building from tags to grow next to. List that category in the district's entries, or the field has no farmhouse.

Pen nodes

Pens are read from the Umland ward only. They are placed near the buildings of their district.

Node Editor name What it does Default
count Count How many pens. 1~1
pawns Animals A PawnListDef with the animals. A missing list gives an empty pen. none
herd Animals per pen. Capped by the pen area. 3~7
plants Plants What grows inside the pen. none
crops Crop list A CropListDef, used instead of plants when set. none
terrain Floor TerrainDef for the pen floor. Empty keeps the map terrain. none
weight Weight Makes this pen larger or smaller. 1

The ward node versorgung (default 1.2) scales the size of all pens in the countryside.

Harbors

A medieval settlement at the coast or on a river of at least flussbreite cells gets a harbor at the shore: jetties, fishing huts, harbor store, harbor master and boat sheds, with a path to the town.

<hafen>
  <entries>
    <li><tag>CBF_MO_Hafenmeister</tag><count>1~1</count></li>
    <li><tag>CBF_MO_Hafenlager</tag><count>1~1</count></li>
    <li><tag>CBF_MO_Steg</tag><count>1~2</count></li>
    <li><tag>CBF_MO_Bootsschuppen</tag><count>0~1</count></li>
  </entries>
</hafen>
Node What it does Default
entries Categories (tag) with a count range. none
flussbreite Smallest river width in cells that counts. The sea always counts. 10
reichweite How far from the settlement harbor pieces may stand, in cells. 45

Harbor pieces need a Connect anchor named Wasser on their water side, see Pieces and categories in XML. Without suitable water no harbor is built.

Tuning fields

These sit on the plan, next to the header fields:

<roadMain>2</roadMain>
<roadLane>2</roadLane>
<targetBuilt>0.62</targetBuilt>
<defenderPoints>400~700</defenderPoints>
<defendersOnWall>0.28</defendersOnWall>
Node Editor name What it does Default
roadMain Main road width Width of the main road. At most 2 for medieval plans, 6 for modern ones. More is a load error. 2
roadLane Lane width Width of the side lanes. Same limits. 1
targetBuilt Target built share Share of the town and suburb area covered by buildings. It sets how large the settlement is planned and how long filler entries keep filling. 0 uses the planner default of 0.62. Shipped medieval plans use 0.5 to 0.62. 0
defenderPoints Defender strength Points for wards without a garrison. 180~420
defendersOnWall Defenders on the wall Share of point-based defenders on the wall, 0 to 1. 0.25
assaultDelayTicks Assault delay Ticks before the defenders attack. 25000

Gaps between buildings are set per ward with abstand. The plan nodes minBuildingGap and maxBuildingGap are only used when the plan has no town ward.

Use targetBuilt to change density.

Older plans put walls, emplacements, gatehouses and districts directly on the plan. That still loads as a single town ward. Use wards for new plans.

How CBF picks a plan for a faction

For every faction base CBF builds a pool of plans, then draws one:

  1. Own plans. Every plan whose factionTags names the faction's defName or its categoryTag.
  2. General plans. Only if step 1 found nothing: every plan with fuerAlleFraktionen set and the faction's tech level in techLevels.
  3. Exclusions. A faction listed in excludeFactions never gets that plan, in either step.
  4. Unusable plans. Plans without a usable material list and plans of the hidden kinds Lager and Verlies are left out.
  5. Tier filter. With World Domination 2.0, only the plans whose wdStufe is closest to the base's tier stay; plans without wdStufe drop out as soon as one plan in the pool has one. With A Rim of Ice and Fire, the faction's main seat prefers plans with wdStufe 3 or more, other bases plans below 3.
  6. Draw. One plan by weight, anteil (0 counts as 1). The draw depends on the world object, so the same base always gets the same plan.

A faction that ends up with an empty pool keeps RimWorld's own base. A place without a faction takes the plans that have no factionTags.

Players can switch single factions back to RimWorld's bases in the mod settings, see Mod settings. A switched-off faction gets no plan, whatever the XML says.

Quest sites work differently. They only take plans that have siteTags.

Tips

  • Start from a shipped plan. Copy it, change defName, label and factionTags, then change one thing at a time.
  • Give a plan for your own faction factionTags and leave fuerAlleFraktionen off. Then it cannot spill over to other factions of the same tech level.
  • Setting fuerAlleFraktionen without techLevels does nothing.
  • A faction with own plans never gets the general ones. If you add one plan for a faction, it loses the shipped general plans. Add enough plans of your own, or none.
  • Use anteil to make a large town rare. The Medieval Overhaul village uses 80, the fortress city 10.
  • Every tag must match a category that has pieces for the loaded mods. A category without pieces places nothing.
  • Put MayRequire on the def node and on every list item that names content from another mod.
  • A very large program on a small map gets cut, and CBF logs a warning with the edge length it needed. Raise mapSize, lower the counts, or raise targetBuilt.
  • Mark the bulk housing of each ward as filler. Fixed buildings are placed first, filler takes what is left.
  • Keep unique for keeps, town halls and similar single buildings.
  • Pens need an Umland ward. Fields need a Vorstadt or Umland ward and a farmhouse category in the same district.
  • The editor preview shows the plan on a flat map. Build a real base afterwards; the terrain of a tile changes a lot.
  • defName is saved with the world. Renaming it later makes existing bases draw a new plan.
