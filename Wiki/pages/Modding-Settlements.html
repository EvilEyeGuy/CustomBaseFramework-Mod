Writing a settlement type in XML

Modding

This guide builds a settlement plan from XML, then explains how wards, districts and building requests work together. The in-game editor writes the same format. Use SettlementPlanDef to check the current field names and initial defaults.

What a settlement type is

A settlement type is a CustomBaseFramework.SettlementPlanDef. It does not contain a map. It is a building program: which wards the place has, which walls, towers and gates protect them, which buildings go where, and which fields and pens lie around it.

Terms used on this page:

  • Ward: one ring of the settlement. The town is in the middle, the suburb around it, the countryside outside.
  • District: a group of buildings inside a ward that stay together, for example a market square or a farm.
  • Piece: one hand-drawn building (a PieceDef), see Pieces.
  • Category: a group of interchangeable pieces (a PieceCategoryDef), for example all taverns.
  • Pawn list: a weighted list of pawn kinds (a PawnListDef), see Pawns.

When a caravan or raid first reaches a base, the generator plans the settlement on the real map of that tile:

  1. It picks one settlement type for the faction.
  2. It lays out the wards as rings.
  3. It builds the walls, places towers and gatehouses, and runs the main road and lanes through the gates.
  4. It splits each ward into districts and places the buildings each district asks for.
  5. It adds fields next to farmhouses and pens in the countryside.
  6. It fills every planned spot with a piece and spawns the defenders.

The settlement type decides what is asked for. The pieces decide what each building looks like.

Minimal example

This example uses CBF’s shipped modern material list and house category. It makes the plan eligible for industrial factions without an explicit faction plan; it does not force every eligible base to choose it.

<Defs>
  <CustomBaseFramework.SettlementPlanDef>
    <defName>MyMod_Plan_Hamlet</defName>
    <label>hamlet</label>
    <kind>ModernTown</kind>
    <materialList>CBF_Modern_MaterialList</materialList>
    <styles>
      <li>CBF_ModernVanilla</li>
    </styles>
    <techLevels>
      <li>Industrial</li>
    </techLevels>
    <forAllFactions>true</forAllFactions>
    <wards>
      <li>
        <kind>Town</kind>
        <districts>
          <li>
            <entries>
              <li><tag>CBF_Vanilla_HouseSmall</tag><count>6~10</count><filler>true</filler></li>
            </entries>
          </li>
        </districts>
      </li>
    </wards>
  </CustomBaseFramework.SettlementPlanDef>
</Defs>
  • kind is ModernTown, so the town needs no wall. The default kind, MedievalTown, expects wall pieces on the town ward. Without them the town stays open and CBF logs a warning.
  • materialList names the shipped modern material list. Without a material list the settlement type is switched off.
  • styles names one of the shipped styles.
  • techLevels together with forAllFactions makes the settlement type available to every industrial faction that has no settlement types of its own. Without any faction settings it is only used for places that have no faction.
  • The load check also needs at least one building entry, a mapSize of 150 or more (default 175) and road widths within the limit of the kind.
  • There is no garrison, so the defenders come from defenderPoints (default 180 to 420).

Header fields

These nodes sit directly on the settlement type. From CBF_Plan_Village_New (Medieval Overhaul village), trimmed:

<CustomBaseFramework.SettlementPlanDef MayRequire="DankPyon.Medieval.Overhaul">
  <defName>CBF_Plan_Village_New</defName>
  <label>village (MO)</label>
  <materialList>CBF_MO_MaterialList</materialList>
  <kind>MedievalTown</kind>
  <styles>
    <li>Rustical</li>
    <li>Standard</li>
  </styles>
  <coreSize>50~60</coreSize>
  <mapSize>200</mapSize>
  <factionTags>
    <li>DankPyon_NobleHouseSavage</li>
    <li>DankPyon_NobleHouseCivil</li>
  </factionTags>
  <forAllFactions>true</forAllFactions>
  <techLevels>
    <li>Medieval</li>
  </techLevels>
  <share>80</share>
  <worldTexture>World/WorldObjects/CBF/CBF_VillagePalisade</worldTexture>
  <wdLevel>1</wdLevel>
</CustomBaseFramework.SettlementPlanDef>

The column "Editor label" gives the name of the field in the editor's settlement tab, where there is one.

MayRequire

MayRequire is RimWorld's own attribute. On the def node it skips the whole settlement type when the mod is missing. On a list item it skips only that item:

<plants>
  <li MayRequire="DankPyon.Medieval.Overhaul">DankPyon_Plant_Wheat</li>
  <li>Plant_Corn</li>
</plants>

Put MayRequire on the def node whenever the settlement type names pieces, categories or pawn lists from another mod. requiredMods alone does not protect a hand-written settlement type.

Wards

A ward is one ring of the settlement. There are three kinds, set with kind:

kind Editor label Layer Notes
Town Town inner The core. Walled if it has wall pieces, otherwise open.
Suburb Suburb middle Optional. Without wall pieces it is an open suburb. Without the ward there is no suburb.
Rural Countryside outer Optional. Never walled. Pens are only placed here.

Write each kind once. The enum also lists Castle, but the planner has no layer of its own for it and treats it like the countryside. Do not use it.

From CBF_Plan_FortressCity_New, the town ward, trimmed:

<wards>
  <li>
    <kind>Town</kind>
    <label>Old town</label>
    <roads>
      <li>DankPyon_Floor_Cobblestone_Granite</li>
    </roads>
    <walls>
      <li><piece>TownWall_1x5</piece><weight>0.75</weight></li>
      <li><piece>CBF_MO_TownWall_1x5_Embrasure</piece><weight>0.25</weight></li>
    </walls>
    <emplacements>
      <li><tag>CBF_MO_FortressTower</tag><count>4~6</count></li>
    </emplacements>
    <gatehouses>
      <li><tag>CBF_MO_FortressGate</tag><count>1~2</count></li>
    </gatehouses>
    <garrison>
      <li><list>CBF_MO_Garrison_Walkway</list><count>16~21</count><post>Walkway</post></li>
      <li><list>CBF_MO_Garrison_Gate</list><count>5~8</count><post>Gate</post></li>
      <li><list>CBF_MO_Garrison_Inside</list><count>8~13</count><post>Inside</post></li>
    </garrison>
    <districts>
      ...
    </districts>
  </li>
</wards>

The shipped file has no label line. It is added here to show the node.

Walls, emplacements and gatehouses

All three are lists of wall entries. An entry is either plain text or a node with fields. From the suburb ward of CBF_Plan_FortressCity_New:

<walls>
  <li><piece>TownWall</piece><weight>0.75</weight></li>
  <li><piece>CBF_MO_TownWall_Embrasure</piece><weight>0.25</weight></li>
</walls>
<emplacements>
  <li><tag>CBF_MO_TownTower</tag><count>3~5</count></li>
</emplacements>
<gatehouses>
  <li><tag>CBF_MO_Gatehouse</tag><count>1~2</count></li>
</gatehouses>
  • walls: the pieces the wall is built from. Plain wall makes up three quarters of the wall, wall with an embrasure one quarter.
  • emplacements: three to five towers from the category CBF_MO_TownTower.
  • gatehouses: one or two gatehouses from the category CBF_MO_Gatehouse, placed where roads cross the wall.

The village uses the plain text form, <li MayRequire="DankPyon.Medieval.Overhaul">Palisade</li>, for its palisade.

Node What it does Default
plain text A PieceDef or PieceCategoryDef name.
piece A PieceDef name. none
tag A PieceCategoryDef name. Every non-template piece in it can be used. none
weight Share of this entry against the other entries of the same list. For walls it sets how often each piece appears along the wall. 1
count For emplacements and gatehouses: how many. 0~0 lets the planner decide. At most 150. 0~0

For all three forms, CBF looks for a piece of that name first, then for a category. A name that is neither is skipped with a warning.

  • A wall piece must be one cell wide in one direction. Its length in the other direction is the wall thickness, 1 to 5 cells: 1 is a palisade, 3 a wall with a walkway, 5 a broad fortress wall.
  • Use pieces of the same thickness within one ward. The thickness comes from the wall pieces.
  • Tower sizes are read from square pieces with an odd edge length.
  • ModernTown and Camp settlements build no gatehouses.

Outworks

Use outworks on a ward for obstacles outside its wall, such as individual stakes or barricade cells. Each selected piece must be 1×1. Larger pieces are skipped, so a normal multi-cell building is not suitable here.

This fragment belongs inside one wards/li. Replace MyMod_Stake with your own 1×1 PieceDef:

<outworks>
  <li>
    <piece>MyMod_Stake</piece>
    <distance>2</distance>
    <spacing>5~9</spacing>
    <run>2~3</run>
    <gateClearance>4</gateClearance>
  </li>
</outworks>

The generator follows a ring two orthogonal cell steps outside the wall. Without a wall it starts from the ward boundary. spacing controls the interval between groups and run the number of candidate cells in each group. Blocked cells are skipped, so group size is a request rather than a guarantee. Gate approaches, roads and squares remain clear.

Use tag instead of piece to select from a category. When both are set, piece wins. Category candidates are chosen uniformly. See Vorfeldspec for defaults and limits.

Garrison

A garrison places fixed defenders in a ward. Each entry names a pawn list, a count and a post.

Node Editor label What it does Default
list A PawnListDef, see Pawns. A missing list leaves the entry empty and logs a warning. none
count Min, Max How many pawns from this list. 1~1
post post Inside (inside the ward), Walkway (on the wall walkway) or Gate (at the gates). The editor shows them as Inside, Wall and Gate. Inside

A ward with a garrison uses only its own entries. A ward without one takes its share of the settlement type's defenderPoints. defendersOnWall (default 0.25) sets how many of those point-based defenders stand on the wall.

Districts and building entries

A district is a group of buildings that stay together. Each ward has one or more districts. A building entry asks for a number of buildings from a category, or for one specific piece.

From CBF_Plan_FortressCity_New, town ward:

<districts>
  <li>
    <name>Castle</name>
    <prefCenter>1</prefCenter>
    <entries>
      <li><tag>CBF_MO_FortressKeep</tag><count>1~1</count><unique>true</unique></li>
      <li><tag>CBF_MO_Barracks</tag><count>2~2</count></li>
      <li><piece>CBF_MO_Dungeon</piece><count>1~2</count></li>
    </entries>
  </li>
  <li>
    <name>Center</name>
    <entries>
      <li><tag>CBF_MO_Tavern</tag><count>1~1</count></li>
      <li><tag>CBF_MO_Church</tag><count>1~1</count></li>
      <li><tag>CBF_MO_BurgherHouse</tag><count>6~14</count><filler>true</filler></li>
      <li><tag>CBF_MO_GapYard</tag><count>0~6</count><filler>true</filler></li>
    </entries>
  </li>
</districts>

The prefCenter line is added for this page. The shipped settlement type leaves the location to the planner.

District nodes

Node Editor label What it does Default
name Internal name. Must be unique across the whole settlement type, a duplicate logs a warning. Fields and pens use it to find their buildings. Default
label Display name. none
entries The building entries. none
prefCenter Near the center Pull toward the center of the ward. 0
prefGate Near the gate Pull toward the gates. 0
prefWall Near the wall Pull toward the wall. 0
prefMain Main road Pull toward the main road. 0
fields, pens See Fields and pens. none
mines Mines dug into the rock from a building of this district, see Minenspec. none

The four location values decide where the district starts. They are weighed against each other, so 1 and 0 means the same as 0.5 and 0. In the editor they are tick boxes under Location of the district, which write 1 or 0. When all four are 0, the district starts as far as possible from the districts already placed.

Building entries

Node Editor label What it does Default
tag A PieceCategoryDef. The planner picks pieces from this category. none
piece One specific PieceDef. none
count Min, Max How many, as a range. More than 150 is cut to 150. 1~1
unique Sets the count to exactly 1. false
filler Filler After the fixed buildings are placed, filler entries fill the free space until targetBuilt is reached. They may go above their maximum. A filler counts as missing only below half its minimum. Fillers in the countryside do not fill. false
weight Wt. Only on piece entries. Changes how often that piece is chosen wherever its category is drawn in this settlement type. 0 turns the piece off. On tag entries it has no effect. 1
lootTable A LootTableDef. Used for loot spots in the pieces of this entry that name no table of their own. A missing table logs a warning. none
withIdeo, withoutIdeo Meme or precept defNames. The entry is only built when the owning faction's ideoligion has (or lacks) one of them. See Settlements. none
  • Name either tag or piece. With both, the piece wins and a warning is logged. With neither, the entry is skipped.
  • Use tag for anything that should vary. Use piece for one building that must appear as drawn, such as a keep or a dungeon.
  • The minimum of an entry is a wish, not a guarantee. If the space runs out, the planner reports what it could not place.

Fields and pens

Fields and pens belong to a district in the suburb or countryside ward. A field is a crop area laid out next to a building of the district. A pen is a fenced area with animals. From CBF_Plan_Village_New:

<li>
  <kind>Rural</kind>
  <districts>
    <li>
      <name>Mill</name>
      <fields>
        <li>
          <count>2~3</count>
          <fence>false</fence>
          <plants>
            <li MayRequire="DankPyon.Medieval.Overhaul">DankPyon_Plant_Wheat</li>
          </plants>
          <tags>
            <li>CBF_MO_Mill</li>
          </tags>
        </li>
      </fields>
      <entries>
        <li><tag>CBF_MO_Mill</tag><count>1~1</count></li>
      </entries>
    </li>
    <li>
      <name>Pasture</name>
      <pens>
        <li>
          <count>1~1</count>
          <herd>2~5</herd>
          <pawns>Hardanimals_1</pawns>
          <terrain>Soil</terrain>
          <plants>
            <li>Plant_Haygrass</li>
          </plants>
        </li>
      </pens>
      <entries>
        <li><tag>CBF_MO_Barn</tag><count>1~1</count></li>
      </entries>
    </li>
  </districts>
</li>

Field nodes

Fields are read from the Suburb and Rural wards. Fields in the town ward are ignored.

Node Editor label What it does Default
count How many fields this entry adds to the ward. 1~1
tags Farmsteads Categories whose buildings get a field next to them. Empty takes the categories of the district's entries. none
plants ThingDefs of the crops. none
crops Crop list A CropListDef with weighted plants. Used instead of plants when set, see Loot. none
fence Fence around the field. false
weight Chance of this field kind when a ward has several. 1

A field needs a building from tags to lie next to. List that category in the district's entries, or the field has no farmhouse.

Pen nodes

Pens are read from the Rural ward only. They are placed near the buildings of their district.

Node Editor label What it does Default
count How many pens. 1~1
name Name of the pen in log messages. Pen
pawns A PawnListDef with the animals. A missing list gives an empty pen. none
herd Herd Animals per pen. Capped at one animal per 12 cells of pen. 3~7
plants Growth What grows inside the pen. none
crops Crop list A CropListDef, used instead of plants when set. none
terrain Soil TerrainDef for the pen floor. Empty keeps the map terrain. none
weight Makes this pen larger or smaller. 1

The ward node supply (default 1.2) scales the size of all pens in the countryside.

Harbors

A settlement at the coast, or on a river at least minRiverWidth cells wide, can get harbor buildings at the shore, such as jetties, fishing huts and boat sheds. harbor sits on the settlement type. From CBF_Plan_MarketCity_New:

<harbor>
  <entries>
    <li><tag>CBF_MO_Harbormaster</tag><count>1~1</count></li>
    <li><tag>CBF_MO_HarborStore</tag><count>1~2</count></li>
    <li><tag>CBF_MO_Jetty</tag><count>2~3</count></li>
    <li><tag>CBF_MO_FisherHut</tag><count>1~2</count></li>
    <li><tag>CBF_MO_Boathouse</tag><count>1~1</count></li>
  </entries>
</harbor>
Node What it does Default
entries A category (tag) or one piece (piece), each with a count range. none
minRiverWidth Smallest river width in cells that counts. The sea always counts. 10
range How far from the settlement harbor pieces may stand, in cells. 45

Harbor pieces need an anchor named Water on their water side, see Pieces and categories in XML. Pieces without it are not used. Without suitable water no harbor is built.

Tuning fields

These sit on the settlement type, next to the header fields:

<roadMain>2</roadMain>
<roadLane>2</roadLane>
<targetBuilt>0.62</targetBuilt>
<defenderPoints>400~700</defenderPoints>
<defendersOnWall>0.28</defendersOnWall>
Node Editor label What it does Default
roadMain Width of the main road. At most 6 for ModernTown, 2 for every other kind. More is a load error. 2
roadLane Width of the side lanes. Same limits. 1
targetBuilt Share of the town and suburb area covered by buildings. It sets how large the settlement is planned and how long filler entries keep filling. 0 uses the planner default of 0.62. Shipped medieval settlement types use 0.5 to 0.62. 0
treeShare Tree share Share of the wild trees inside the settlement that stay standing, 0 to 1. 0
defenderPoints Points for defenders of wards without a garrison. 180~420
defendersOnWall Share of point-based defenders on the wall, 0 to 1. 0.25

Gaps between buildings are set per ward with buildingGap. The settlement type nodes minBuildingGap and maxBuildingGap are only used when there is no town ward.

Use targetBuilt to change density.

Older settlement types put walls, emplacements, gatehouses and districts directly on the def. That still loads as a single town ward. Use wards for new settlement types.

How CBF picks a plan for a faction

For every faction base, CBF builds a pool of settlement types, then draws one:

  1. Own types. Every settlement type whose factionTags names the faction's defName or its categoryTag.
  2. General types. Only if step 1 found nothing: every settlement type with forAllFactions set and the faction's tech level in techLevels.
  3. Exclusions. A faction listed in excludeFactions never gets that settlement type, in either step.
  4. Unusable types. Settlement types without a material list, of the kind Dungeon, or with campTypes or riafHolding are left out.
  5. Tier filter. With World Domination 2.0, a base with a tier only keeps settlement types that have a wdLevel, and of those the ones closest to its tier. Among these, types whose wdType names the base's World Domination type win. Otherwise types without wdType are preferred. If no type in the pool has a wdLevel, the base keeps RimWorld's own map. With A Rim of Ice and Fire, the faction's main seat prefers settlement types with wdLevel 3 or more, other bases types below 3.
  6. Draw. One settlement type by weight, share (0 counts as 1). The draw depends on the world object, so the same base always gets the same settlement type.

A faction that ends up with an empty pool keeps RimWorld's own base. A place without a faction takes the settlement types that have no factionTags.

Players can switch single factions back to RimWorld's bases in the mod settings, see Mod settings. A switched-off faction gets no settlement type, whatever the XML says.

Quest sites use siteTags for automatic plan selection. A fixed usable plan supplied by a quest or site extension bypasses that filter. Quest camps, such as bandit camps and outposts, take settlement types of the kind Camp whose campTypes name the site.

Tips

  • Start from a shipped settlement type. Copy it, change defName, label and factionTags, then change one thing at a time.
  • Give a settlement type for your own faction factionTags and leave forAllFactions off. Then it cannot spill over to other factions of the same tech level.
  • Setting forAllFactions without techLevels does nothing.
  • A faction with own settlement types never gets the general ones. If you add one settlement type for a faction, it loses the shipped general ones. Add enough of your own, or none.
  • Use share to make a large town rare. The Medieval Overhaul village uses 80, the fortress city 10.
  • Every tag must match a category that has pieces for the loaded mods. A category without pieces places nothing.
  • Put MayRequire on the def node and on every list item that names content from another mod.
  • A very large program on a small map gets cut, and CBF logs a warning with the edge length it needed. Raise mapSize, lower the counts, or raise targetBuilt.
  • Mark the bulk housing of each ward as filler. Fixed buildings are placed first, filler takes what is left.
  • Keep unique for keeps, town halls and similar single buildings.
  • Pens need a Rural ward. Fields need a Suburb or Rural ward and a farmhouse category in the same district.
  • The editor preview shows the settlement type on a flat map. Build a real base afterwards; the terrain of a tile changes a lot.
  • defName is saved with the world. Renaming it later makes existing bases draw a new settlement type.
